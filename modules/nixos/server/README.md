# server

The home-server's service stack — imported only by `hosts/home-server`.
Everything here is deliberately absent from the workstation `base`.

| File               | Configures                                                   |
|--------------------|-------------------------------------------------------------|
| `ssh.nix`          | OpenSSH re-enabled (key-only, no root), admitted **only on the `wg0` VPN interface** — never the WAN. |
| `wireguard.nix`    | WireGuard **server** (`wg0`, `10.100.0.0/24`, the box is `.1`). Private key is a sops secret (`secrets/home-server/wireguard.yaml`), decrypted at activation; client public keys added to `peers`. UDP 51820 is the only WAN port. |
| `ipv6-interface-id.nix`| **Fixed IPv6 interface ID** for the LAN link (`enp5s0`), as a NetworkManager keyfile in `/etc`. The router forwards inbound IPv6 via an *exposed host* entry pinned to a hand-entered interface ID; NM's default `stable-privacy` hashes the /64 prefix into that ID, so the nightly prefix rotation broke inbound every night. `ipv6.token` pins the low 64 bits — change it here and in the FRITZ!Box together. Not `ensureProfiles`: that unit runs after NM has already auto-generated a profile and come up on the wrong address. |
| `reverse-proxy.nix`| **Nginx Proxy Manager** container (LE certs + proxy hosts via its web UI), running with **`--network=host` and no published ports** — podman's publish DNAT is IPv4-only here, and the box is IPv6-only inbound, so published ports left `:80`/`:443` refusing over v6 (which is what broke ACME). Public HTTP/HTTPS on `80`/`443`; admin UI on `81`, **VPN-only by firewall** (the input chain governs it now that there is no DNAT). Upstreams must be `127.0.0.1` in the UI, not the podman bridge gateway. Data under `/hdd_pool_1/services/npm`. Certs via **DNS-01** (Cloudflare credential entered in NPM's UI, not the sops secret). Hardened: no socket mount, `no-new-privileges`. |
| `cloudflare-ddns.nix`| **Dynamic DNS**: publishes the box's current public IPv6 into Cloudflare's proxied AAAA record for `*.mauderer.work` every 5 min (`services.cloudflare-dyndns`, AAAA only). API token is a sops secret (`secrets/home-server/cloudflare.yaml`, key `cloudflare-api-token`, **bare token**). Also disables IPv6 privacy extensions so the published address is the stable one. |
| `containers.nix`   | Container-host groundwork for docker-compose / Ansible services. |
| `forgejo.nix`      | **Self-hosted forge** (`services.forgejo`, SQLite, LFS), served as `https://git.mauderer.work` through NPM. Prometheus `/metrics` on, and **token-gated** — the only metrics endpoint here that is not loopback-only, because it rides on the listener NPM publishes; the token is a sops secret (`secrets/home-server/forgejo.yaml`, key `forgejo-metrics-token`, **bare value**) handed to both Forgejo and Prometheus as a systemd credential, never through `settings`. HTTP `:4000` admitted only from the podman bridge (the proxy) and the VPN (admin access at `http://10.100.0.1:4000`), built-in git-SSH `:2222` only from LAN/VPN — no new WAN ports. Self-registration off, Actions on, `DEFAULT_ACTIONS_URL = github`, push mirroring on (GitHub is the backup target). State on the SSD; nightly `forgejo dump` to `/hdd_pool_1/services/forgejo/dump`. |
| `forgejo-runner.nix`| **Forgejo Actions runner** (`services.forgejoRunner`, **opt-in**, default off). Jobs run as podman containers via `forgejo-runner`. Registration token is a sops secret (`secrets/home-server/forgejo.yaml`, key `forgejo-runner-token`, **`TOKEN=…` env-file format**). Runs as a host service holding the rootful podman socket — root-equivalent, hence single-user-forge only. |
| `paperless.nix`    | **Document archive** (`services.paperless`, SQLite, OCR `deu+eng`). HTTP `:28981` admitted **only on `wg0`** — deliberately *not* published through NPM, so it has no WAN surface at all (`http://10.100.0.1:28981`). All state, media and the nightly `document_exporter` run live on the ZFS pool under `/hdd_pool_1/services/paperless`; the drop folder is `/hdd_pool_1/share/paperless-inbox`, inside the NFS export. Admin password is a sops secret (`secrets/home-server/paperless.yaml`, key `paperless-admin-password`, **bare password**). |
| `ntfy.nix`         | **Push notifications** (`services.ntfy-sh`), served as `https://ntfy.mauderer.work` through NPM so notifications arrive off-LAN — the opposite exposure call from `paperless.nix`, and the reason the instance is closed: `auth-default-access: deny-all`, no self-signup, `behind-proxy` on. HTTP `:2586` admitted only from the podman bridge (the proxy) and the VPN — no new WAN ports. Attachments deliberately off — `attachment-cache-dir` is blanked, which the module has to do explicitly because upstream defaults it to a real path, so it is not a public upload target. State is the auth db + a 12 h message cache under `/var/lib/ntfy-sh` on the SSD — no ZFS pool path, hence no mount-ordering oneshot. **No sops secret**: users/tokens are created with the `ntfy` CLI (as root — `DynamicUser` puts the db under `/var/lib/private`), because the declarative `auth-users` route would put bcrypt hashes and live tokens in the world-readable Nix store. Prometheus metrics via `metrics-listen-http` on a **separate** loopback listener (`127.0.0.1:9686`), never `enable-metrics` — that option serves `/metrics` from the main listener, which is the one NPM publishes to the WAN. |
| `postgresql.nix`   | **Shared database server** (`services.postgresql`, pinned `postgresql_18`) for services added later — ships as an empty cluster, no databases or roles. Reachable over the Unix socket **only**: `listen_addresses` is forced to `""`, because `enableTCPIP = false` alone still binds `127.0.0.1:5432`. No firewall rule exists or is needed. Local auth is upstream's **peer** default, so a role is reachable only by the system user of the same name and no password lands in sops. Cluster on the SSD (`/var/lib/postgresql/18`); nightly `pg_dumpall` to `/hdd_pool_1/services/postgresql/dump` (zstd, current + one `.prev` only). Declares its own **postgres_exporter** on `:9187` (loopback) — `runAsLocalSuperUser` puts it on the socket as the `postgres` system user, so peer auth covers it and no credential exists anywhere. |
| `metrics.nix`      | **Prometheus** (`:9090`) plus the **node** (`:9100`) and **smartctl** (`:9633`) exporters — CPU/memory/disk/network/ZFS-ARC metrics, systemd unit state, and SMART drive health for the pool disks. All three bind `127.0.0.1` and are never firewalled open: Prometheus scrapes the two exporters over loopback, and Grafana queries Prometheus from the same host, so nothing here is read from off the box. TSDB on the SSD (`/var/lib/prometheus2`, `services.prometheus.stateDir` is `/var/lib`-relative), bounded at 90 days / 20 GiB. The node exporter also runs the **textfile** collector over `/var/lib/node-exporter-textfile`, which is how `nixos-metrics.nix` and `backup-metrics.nix` get their series in. Also scrapes the services' own endpoints: **ntfy** (`:9686`, its dedicated loopback metrics listener), **postgres_exporter** (`:9187`, socket + peer auth, no credential) and **Forgejo** (`:4000`) — Forgejo being the one target that is not loopback-only, hence the only one that carries a bearer token. That token is why `checkConfig` is `syntax-only`: the full `promtool check config` stats every referenced file, and a systemd credential does not exist at build time. |
| `nixos-metrics.nix`| **Update-pipeline metrics** — an hourly oneshot + timer writing a `.prom` file into `/var/lib/node-exporter-textfile`, which the node exporter's **textfile collector** re-exports on `:9100`. Opens no socket. Answers what the hardware exporters cannot: is a reboot pending (compares the *kernel/initrd/kernel-modules* links of `/run/booted-system` and `/run/current-system` — comparing toplevel paths would read "yes" after every rebuild), when did `nixos-upgrade`/`nix-gc`/`nix-optimise` last finish and with what exit code, how old is the nixpkgs behind the running system (parsed from `nixos-version`, so a stalled `update-lock.yml` shows up), and how many generations / store paths are retained. Written to a `.tmp` and renamed: the collector parses whatever it finds, and a partial file poisons the entire scrape. Nothing expires a stale file, so `node_textfile_mtime_seconds` is the freshness guard. |
| `backup-metrics.nix`| **Backup freshness metrics** — an hourly oneshot writing a second `.prom` file into the same textfile directory, covering the three nightly backups (`forgejo dump`, paperless `document_exporter`, `pg_dumpall`). Measures the *files*, not the units: the systemd collector already shows a backup unit that fails, but not the failure that actually loses data — a unit exiting 0 having written nothing, a timer that stopped firing, or a dump that has been shrinking for a week. Reports zeros rather than nothing for a missing directory, because an absent sample cannot be alerted on. Ordered `after` (never `Requires`) `zfs-mount.service`, so a pool that fails to mount does not also silence the metric that would say so. |
| `blackbox.nix`     | **Synthetic probes** (`prometheus.exporters.blackbox`, `:9115` loopback — an exporter that fetches URLs on request must never be reachable from off the box). Probes the services the way a client does. **These do not prove internet reachability** — the prober runs on the box being probed, so a public hostname either hairpins through the router or never leaves; verifying that needs an off-box prober this repo does not have. What they do prove: **certificate expiry and proxy routing**, by connecting to `127.0.0.1:443` (NPM publishes `:443` on all interfaces) with the real hostname as SNI *and* Host header — the full TLS-termination-and-routing chain, no DNS or hairpin needed, with certificate verification genuinely on (`tls_config.server_name`, never `insecure_skip_verify`); **public DNS**, by asking a public resolver for each hostname's AAAA, which is what shows a stalled `cloudflare-ddns`; and loopback health endpoints. One prober module per hostname, because SNI and `query_name` are per host. |
| `alerts.nix`       | **Alert delivery**, both halves, in one file. (1) A `notify-failure@` systemd template wired as `OnFailure=` onto the units whose failure matters (the three backups, `nixos-upgrade`, `zfs-scrub`, the stack itself, both `.prom` writers). It POSTs the failing unit's name plus its last 15 journal lines to the local ntfy — no scrape, no evaluation interval, no database, so it still works when the observability stack *is* what broke. (2) Grafana unified alerting: 11 provisioned rules (target down, unit failed, filesystems filling, SMART failure, backup stale **or empty**, certificate expiring, probe failing, nixpkgs stale, reboot pending, textfile stale), a notification policy routing everything to ntfy, and the contact point. Every rule sets `noDataState = OK` — Grafana's default alerts on an *absent* series, and absence is the healthy state for all of these by construction. The contact point is generated into `/run` by a oneshot inside grafana.service's dependency chain, never `provision.alerting.contactPoints.settings`, which would render the publish password into the world-readable Nix store. ntfy's `template=yes` turns Grafana's JSON body into a readable title/message. Credential: `secrets/home-server/ntfy.yaml`, key `ntfy-alert-password`, **bare value** — a password, not a token, so sops is authoritative and `ntfy user add` on the server consumes it rather than the reverse. |
| `logs.nix`         | **Loki** log store (`:3100`) + **Grafana Alloy** shipping the systemd journal into it. `:3100` is push *and* query with no authentication, so it is admitted by a source-restricted rule from the podman bridge, LAN and VPN only — that restriction *is* the access control. Chunks, index and compactor on the pool under `/hdd_pool_1/services/loki`, 90-day retention. |
| `grafana.nix`      | **Grafana** (`:3030` — off the reserved 3000-3010 range), admitted **only on `wg0`** and deliberately *not* proxied through NPM, so it has no WAN surface (`http://10.100.0.1:3030`). Prometheus + Loki datasources provisioned from Nix, as are the six baseline dashboards in `dashboards/` (`host.json`, `logs.json`, `nixos.json`, `services.json`, `stack.json`, `uptime.json` → a read-only **NixOS** folder); the General folder stays UI-owned for scratch dashboards and pasted-in community JSON. Provisioned dashboards can't be saved from the UI — export the JSON, replace the file, rebuild. SQLite state on the pool at `/hdd_pool_1/services/grafana`. Two sops secrets in `secrets/home-server/grafana.yaml` (**bare values**, owned by `grafana`, read via Grafana's `$__file{}` provider): `grafana-admin-password`, and `grafana-secret-key` — the key encrypting secrets *inside* Grafana's database, which nixpkgs now requires and which must not be rotated once anything is stored. |
| `zfs.nix`          | Imports the pre-existing **ZFS data pool** (`extraPools`, `hdd_pool_1`) on the RAID LUN; monthly scrub. OS lives on a separate ext4 SSD. |
| `nfs.nix`          | NFSv4 export of `/hdd_pool_1/share` to the LAN + VPN subnets only (edit `lanSubnet`). |

The OS-disk layout is in `hosts/home-server/disk.nix`; the ZFS `hostId` is in
`hosts/home-server/hardware.nix`.

`/hdd_pool_1/services` is shared by `reverse-proxy.nix`, `forgejo.nix`,
`paperless.nix`, `postgresql.nix`, `logs.nix` and `grafana.nix`. Their six
directory-creating oneshots have no ordering between them, so they all leave that
parent as `root:root 0755` — traversable, so each unprivileged service reaches
its own subtree, which stays `0750` (`0700` for the Postgres dump, which holds
every database and role). Changing that mode in one module without the others
locks a service out of its own data.

The same six oneshots also `chmod 0755` the pool **root** `/hdd_pool_1`, because
nothing else in the repo owns its mode: `zfs.nix` imports the pool untouched, so
the mountpoint keeps whatever the box's former Proxmox install set — which was
`0750 maudi:polkituser`, not traversable by any service user. A service running
unprivileged with a `WorkingDirectory` on the pool then fails at systemd's
`CHDIR` step before it ever executes (this is what broke `grafana.service`).
Ownership is deliberately left alone — `maudi` owning the mountpoint may matter
for local access to `/hdd_pool_1/share` — and only the `o+x` bit is needed.

Every one of those oneshots exists for the same reason: `systemd.tmpfiles` runs
before `zfs-mount.service`, so a module that declares a directory on the pool the
normal way gets it created under the *unmounted* mountpoint and then hidden. Each
unit is `requiredBy`/`before` its own consumers and `after zfs-mount.service`,
which also orders the consumers after the mount for free.

To give a new service a database, declare it from that service's own module:

```nix
services.postgresql.ensureDatabases = [ "myservice" ];
services.postgresql.ensureUsers = [
  { name = "myservice"; ensureDBOwnership = true; }
];
```

Peer auth then maps the unit's system user onto the role of the same name — no
password, no host, no port. A *containerised* consumer cannot reach a Unix
socket: bind-mount `/run/postgresql` into it rather than re-enabling TCP.
